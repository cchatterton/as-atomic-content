Merge tokens

A token is a placeholder that a renderer replaces with a value. The same Card can then show different content in different places. There are two related token systems here, and their syntax and source of values matter.

Card placeholders in AlphaCard

AlphaCard scans Card Markup for placeholders wrapped in two percent signs, such as %%title%% or %%button_url%%. After a Card is selected in AlphaCard, the editor shows an input for each distinct placeholder. Type the value there and save the page.

For example, Card Markup could contain <h3>%%title%%</h3>. If the editor enters “How we help” for title, that value appears in the heading. An empty or missing value becomes an empty string. AlphaCard inserts entered values as supplied, including HTML, so only enter markup or URLs that are appropriate for the template.

Names such as %%$post->post_title%% are still just input names in AlphaCard. They do not automatically read a WordPress post. When switching an AlphaCard row to another Card, matching token values are carried over; non-matching values remain available under Non-matching content.

Context tokens in AlphaBlock

AlphaBlock resolves its own tokens in query settings from the post containing the block. These are single-percent tokens, including:

TokenMeaning
%me% or %me->ID%ID of the page or post containing AlphaBlock.
%me-slug% or %me->slug%Slug of that page or post.
%mine->meta_key%Named metadata value on that page or post.

For example, a relationship filter can use %me% to find FAQs related to the current page. AlphaBlock replaces supported tokens before building its query. Unknown tokens remain literal. The older %mine% spelling is context-dependent; prefer the explicit forms in new configurations.

Choose the right token workflow

  • Use AlphaCard when an editor should type the value for each placement.
  • Use AlphaBlock when the value should come from queried posts or the page containing the block.
  • Check the preview and a published page after changing a Card template or query token.
